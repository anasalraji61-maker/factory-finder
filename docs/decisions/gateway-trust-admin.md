# gateway-trust-admin decisions

- 2026-10-15: Supplier verification routes (`/v1/trust/verification/*`) share the `X-Supplier-Id` forwarding block of `/v1/my/*`; no verified claim -> 403 `supplier_claim_required` (new gateway error). Why: trust request asked for 403 and the DB-derived claim is the only trusted source.
- 2026-10-15: Only `GET /v1/trust/suppliers/{id}/verification` was made public (regex in `routing.py`). The request says `GET /v1/trust/suppliers/{id}` "stays public", but today it is authenticated (tests assert so); widening public exposure was left out. Why: smallest change, no new anonymous surface beyond the badge.
- 2026-10-15: Non-GET on trust verification counts as a sensitive write (email-verified when enabled) and the body is capped at 64 KiB (metadata only).
- 2026-10-15: Admin passthroughs for trust/freight/feed live in one module (`api/admin_services.py`) driven by an explicit (method, path-regex) allow-list per service instead of a catch-all like moderation. Why: these services' admin APIs are fixed and small; unknown paths 404 without reaching upstream. Trust keeps the same gateway admin guard as the other admin routes (the request's "admin users only" = `FF_GATEWAY_ADMIN_TOKEN`, as there are no admin user roles in the gateway), and `X-Reviewer` is the fixed `admin` actor, not a user id.
- 2026-10-15: Console never renders document numbers: `lib.safeDoc` whitelists fields (file paths reduced to a count, `number_masked`/fingerprints dropped, audit `detail` dropped), covered by node tests.
- 2026-10-15: Console Freight tab covers applications, forwarders, reports and sweep; freight request/quote hide and feed comments/posts hide are reachable through the passthrough, UI covers feed posts/comments but not freight requests/quotes.
