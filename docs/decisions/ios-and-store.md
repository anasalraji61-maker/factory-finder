# ios-and-store decisions

- 2026-10-15: Platform patching lives in `apps/mobile/tool/ci_prepare_platforms.sh` (python3 plistlib + regex, idempotent), because android/ios folders are generated by `flutter create` and not checked in. Why: keeps Dart and checked-in config untouched, same script for local and CI.
- 2026-10-15: Android: INTERNET, CAMERA, READ_MEDIA_IMAGES, READ_EXTERNAL_STORAGE with maxSdkVersion=32, camera uses-feature required=false; cleartext HTTP only in `src/debug` manifest (local gateway 10.0.2.2); label "مُوَرِّد / Factory Finder".
- 2026-10-15: iOS: NSPhotoLibraryUsageDescription, NSCameraUsageDescription (ar + en in one string), CFBundleDisplayName, CFBundleLocalizations [ar,en]; ATS untouched (script only warns if NSAllowsArbitraryLoads is present). No microphone key (no video).
- 2026-10-15: New `.github/workflows/ios.yml` (macos-latest, `flutter build ios --simulator --debug --no-codesign`, mock mode, no secrets, no artifacts). Existing `mobile.yml` is not modified, so it does not yet call the script (follow-up: have mobile.yml's platform step call it).
- 2026-10-15: Store listing, privacy policy and terms are drafts (`docs/STORE_LISTING.md`, `PRIVACY_POLICY.draft.md`, `TERMS.draft.md`); data-safety answers reflect "no analytics, no card data, no device location". Known blockers before store submission: no in-app account deletion, no Firebase/FCM in the app, release signing not set up.
