# trust (port 8104)

Explainable supplier trust score 0-100 with band green (>=75) / yellow (50-74) / red (<50) / unknown (<4 known signals). Hard caps: sanctions hit -> red, <=20; dispute rate >=8% -> <=69, >=15% -> <=49; price < 0.4x market -> <=59. Every factor has a signed integer impact plus `explanation` / `explanation_ar`.

v2 (model `trust-v2`): extra signals (business-licence status, certificate records with expiry, repeat-buyer rate, response time, refund rate, recency-weighted disputes, on-platform deal outcomes, storefront age, accepted buyer reports); Bayesian shrinkage for ratings and deal completion; `confidence` (0-100 int, evidence coverage x sample depth), `data_gaps` (missing signals, en+ar; missing never lowers the score), `flags` (price_anomaly, certification_expired, ...). Hard fail: `sanctions_hit` or `blocked` -> red, <=20.

Endpoints: `GET /v1/trust/suppliers/{id}/history` (oldest-first; deterministic mock points + stored snapshots), `POST /v1/trust/suppliers/{id}/report` (needs `X-User-Id`; type enum + text<=1000; stored `pending_review`, no score effect until a moderator accepts via `TrustService.review_report`; 429 + Retry-After past `FF_TRUST_REPORT_RATE_LIMIT`/`FF_TRUST_REPORT_RATE_WINDOW_SECONDS`, default 5/hour/user). Stores are in-memory. Also: `GET /v1/trust/suppliers/{id}` (TTL cache), `GET /v1/trust/suppliers:batch?ids=a,b`, `POST /v1/trust/evaluate`, `GET /health`. Contract: `contracts/openapi/trust.yaml`.

Run: `uvicorn ff_trust.main:app --port 8104`. Test: `../../.venv/bin/python -m pytest -q`.

Env: `FF_TRUST_ADAPTER` (mock default; alibaba/made_in_china are disabled stubs), `FF_TRUST_CACHE_TTL_SECONDS` (300), `FF_TRUST_MAX_BATCH` (50), `FF_INTERNAL_TOKEN` (optional), `FF_TRUST_REPORT_RATE_LIMIT` (5), `FF_TRUST_REPORT_RATE_WINDOW_SECONDS` (3600), `FF_TRUST_HISTORY_MONTHS` (12).
Mock ids: any id works (sha256-derived); curated `sup_demo_gold|avg|scam|sanctioned`.


## Ops (logging / readiness)
`GET /ready` (unauthenticated, exempt from the internal token): 200 when the database answers, else 503 (`checks.database`). Each request emits one JSON log line on stdout (`ts, level, service, request_id, method, path` (route template), `status, duration_ms, user_id`); never query strings, tokens or Authorization. `X-Request-Id` is accepted (safe charset, <=64 chars) or generated and echoed back. `FF_LOG_FORMAT=text` for dev. Code: `obs.py` (self-contained copy).

## Review summary signal (rfq)
Optional signal `review_summary` (count, average, histogram, sub_ratings, completed_deals; `rfq.yaml#ReviewSummary`) adds the factor `platform_reviews` (weight 6, bounded +-6): Bayesian shrinkage (`platform_review_prior_weight` 8 towards `review_prior_mean`), 30% blended with the mean sub-rating, then linearly dampened below 10 reviews (`platform_review_full_n`); evidence line en+ar says "small sample dampened". Absent summary = no factor, never a data gap, score unchanged. It is separate from `rating_avg` (marketplace ratings), so nothing is double counted. `evaluate` accepts it inline.
`clients/reviews.py`: `HttpReviewsClient` (GET `{base}/v1/suppliers/{id}/review-summary`, timeout, 60 s cache, any error/non-200/bad JSON -> None = score without it), `MockReviewsClient` (deterministic). Env: `FF_TRUST_REVIEWS_SOURCE` (`off` default | `mock` | `http`), `FF_TRUST_REVIEWS_BASE_URL` (http://rfq:8105), `FF_TRUST_REVIEWS_TIMEOUT_SECONDS` (2), `FF_TRUST_REVIEWS_CACHE_TTL_SECONDS` (60). Scores are cached by the service TTL (300 s), so new reviews show up within that window.

## Supplier verification documents
A supplier (gateway-verified `X-Supplier-Id`) submits document metadata: `doc_type` (business_license, company_registry_reference, bank_reference, export_license, factory_photos, iso_certificate, other_certificate), `issuing_country` (ISO alpha-2), `files` (media-service paths `/v1/media/files/<id>.<ext>`), `number` (required except for photos), optional `expires_on`, `consent: true`. The number is never stored: HMAC fingerprint (duplicates) + masked suffix (`****1234`, owner only). Owner: `POST|GET /v1/trust/verification/documents`, `DELETE .../{id}` (withdraw). Public: `GET /v1/trust/suppliers/{id}/verification` (badge + document types only).
Admin (`X-Admin-Token`; 404 if `FF_TRUST_ADMIN_TOKEN` unset, 401 if wrong; optional `X-Reviewer`): `GET /v1/admin/trust/verification/documents?status=pending`, `POST .../documents/{id}/decision` (`approve`/`reject`; reason required to reject or revoke), `PUT .../documents/{id}/expiry`, `GET .../audit` (append-only, newest first).
States: pending -> approved|rejected|withdrawn; approved -> rejected (revoke)|withdrawn; rejected/withdrawn terminal. Expired is derived.
Scoring: only approved documents; factors `document_verification` (max +6) and `facility_evidence` (max +4), reward-only, same type counted once, decay from 90 days before expiry to 50% at expiry then 0 (no expiry = 730 days after approval); never a data gap. `verification_level` (none/basic/documented/audited) is additive on every TrustScore (audited also needs `third_party_audit`; sanctioned/blocked -> none). Inline `verification` is accepted by `/evaluate`.
Caps: `FF_TRUST_VERIFICATION_RATE_LIMIT` (10/supplier/window, `..._RATE_WINDOW_SECONDS` 3600), `..._MAX_DOCS_PER_TYPE` (5), `..._MAX_DOCS_PER_SUPPLIER` (30), `..._MAX_TOTAL_DOCS` (20000), `..._MAX_FILES` (10). Other env: `FF_TRUST_ADMIN_TOKEN`, `FF_TRUST_VERIFICATION_HASH_KEY` (keys the document-number fingerprints; REQUIRED when `FF_ENV=production`, else the service refuses to start; unset in dev = a random key persisted in `trust_meta` so restarts keep working), `FF_TRUST_VERIFICATION_MEDIA_PREFIXES` (JSON list), `FF_TRUST_VERIFICATION_MEDIA_HOSTS` (JSON list; empty = relative paths only), `FF_TRUST_VERIFICATION_ALLOW_HTTP`.
Storage: the service database (see Persistence). Decisions: `docs/decisions/trust-verification-docs.md`; gateway routing: `docs/requests/trust-verification-gateway.md`.

## Persistence
SQLAlchemy 2 async, same pattern as feed/rfq. `FF_TRUST_DATABASE_URL` (default `sqlite+aiosqlite:///./data/trust.db`, the `data/` dir is created on start; `postgresql://` works with the `pg` extra: `pip install -e "services/trust[pg]"`). `FF_TRUST_DB_AUTO_CREATE` (unset = true for SQLite, false for PostgreSQL: run `alembic upgrade head` first). Tables (`db.py`, migration `migrations/versions/0001_initial.py`): `verification_documents`, `verification_audit`, `reports`, `score_snapshots`, `trust_meta`.
- Audit log: append-only. No update/delete API, and database triggers reject UPDATE/DELETE (SQLite and PostgreSQL). No cap and no purge: archive in the database if it grows.
- Transitions: one transaction = conditional `UPDATE ... WHERE id=? AND status=<read status>` (rowcount checked) + audit insert, so concurrent approve/approve or approve/withdraw cannot both win (409 `invalid_transition`). SQLite takes the write lock at `BEGIN`; PostgreSQL serialises submissions per supplier / reports per user with an advisory lock. A partial unique index (`supplier_id, number_fingerprint` where live) backs the duplicate check.
- Rate limits are derived from stored rows (audit `submit` rows, `reports` rows), so they survive restarts.
- Bounds: `FF_TRUST_VERIFICATION_MAX_TOTAL_DOCS` (only closed docs are evicted, else 503), `FF_TRUST_REPORT_MAX_TOTAL` (20000; evicts rejected, then pending; accepted never, else 503), `FF_TRUST_REPORT_RETENTION_DAYS` (365; rejected and stale pending purged, accepted kept), `FF_TRUST_SNAPSHOT_MAX_PER_SUPPLIER` (500), `FF_TRUST_SNAPSHOT_MAX_TOTAL` (200000), `FF_TRUST_SNAPSHOT_RETENTION_DAYS` (730). Purge runs at startup and at most hourly on writes.
- Startup stores a check value of the hash key; a different key later aborts startup in production (warns elsewhere), because old fingerprints would silently stop matching.
- Tests set `FF_TRUST_DATABASE_URL=sqlite+aiosqlite:///:memory:` (`tests/conftest.py`). Decisions: `docs/decisions/trust-persistence.md`.
